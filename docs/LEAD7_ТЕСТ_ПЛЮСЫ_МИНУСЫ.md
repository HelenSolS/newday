# Тест марафона 7 дней (n8n) — плюсы и минусы

## Что тестируем сейчас

- Один марафон (7 дней), три воркфлоу в n8n: save progress, get progress, finish + promo.
- Фронт: вкладка «Марафон 7 дней» → вызовы в n8n, прогресс в Neon.

## Чеклист теста

- [ ] **Локально (localhost):** Открыть марафон → отметить день 1 → проверить в Neon, что запись в `lead7_day_progress` появилась.
- [ ] **Локально:** Отметить все 7 дней → нажать «Получить промокод» → промокод отображается, в `promo_code` есть запись.
- [ ] **Vercel:** То же самое после деплоя — марафон работает без FastAPI.
- [ ] **Разные устройства/браузеры:** Новый `external_id` (другой localStorage) — новый участник, прогресс не смешивается.
- [ ] **Повторный запрос промокода:** Тот же участник второй раз на «Получить промокод» — получает тот же промокод (не дублируется), без ошибки.

## Идеи для универсальных воркфлоу (потом)

Если тест ок, можно вынести общую схему:

- **Один набор воркфлоу** под «любой марафон»: параметр `marathon_id` или `marathon_slug` (например `lead7`, `lead21`).
- Таблицы в Neon: не только `lead7_*`, а общие `marathon`, `marathon_day`, `marathon_progress`, `marathon_content` и т.д.
- Фронт: список марафонов из конфига или из API n8n, один и тот же UI подстраивается под длину марафона (7, 10, 21 день).
