## 1. МОДУЛЬНЫЙ ПОДХОД (ОБЯЗАТЕЛЬНО)

Любая доработка должна:

- быть **изолирована** (отдельный модуль, компонент или файл);  
- минимально изменять уже существующий код;  
- **не менять сигнатуры и контракты** существующих функций/компонентов без крайней необходимости;  
- **не ломать существующий UI, API и типы**.

Если требуется изменить текущую функцию/модуль:

- сначала предложи:  
  - расширение через **обёртку (wrapper)**,  
  - новую версию (`someFunctionV2`),  
- только после явного подтверждения можно менять поведение существующей логики.

## 2. ОБРАТИМОСТЬ И GIT‑ДИСЦИПЛИНА

Каждое изменение должно:

- быть отдельным, логически цельным коммитом;  
- иметь понятное сообщение (`feat: add course progress`, `fix: handle empty enrollment`);  
- быть легко откатываемым через `git revert`;  
- затрагивать **только одну логическую область** (например, только UI или только API).

**Запрещено:**

- делать большие каскадные изменения “всё сразу”;  
- менять одновременно UI + API + DB в одном коммите;  
- удалять код без явно сформулированной причины в описании коммита или PR.

## 3. СТРУКТУРА ВЕТОК

- `main` — production  
- `dev` — рабочая ветка  
- `feature/*` — для отдельных задач / крупных изменений (опционально)

**Правила веток:**

- ❌ Нельзя пушить напрямую в `main`.  
- ❌ Нельзя мержить без Pull Request.  
- ❌ Нельзя пушить, если `npm run build` падает.

**Порядок работы с задачей:**

1. `git checkout dev`  
2. `git pull`  
3. Внести изменения  
4. `npm run build`  
5. Если build успешен:  
   - `git add .`  
   - `git commit -m "feat: …"`  
   - `git push origin dev`  
6. Создать Pull Request `dev → main`  
7. Проверить, что:  
   - build зелёный  
   - preview‑деплой работает  
8. Только после этого выполнять merge.

## 5. РАБОТА С БД И ENV

### 5.1 Миграции

- Любые изменения БД — только через миграции.  
- Никаких ручных `ALTER TABLE` в production.  
- Миграции лежат в `/sql/migrations/`.  
- Имя миграции содержит timestamp.  
- По возможности миграции должны быть идемпотентны.

### 5.2 Переменные окружения

**Запрещено:**

- хардкодить пароли, токены, ключи;  
- коммитить `.env` и другие файлы с секретами.

**Обязано:**

- использовать `.env.local` локально;  
- на сервере/Vercel использовать Environment Variables.
